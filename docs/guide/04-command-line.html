Phase 4 — The command line

Guide contents · previous: Phase 3 — The GUI in depth · next: Phase 5 — Understanding what you see

Everything the window does is also available in a terminal: assemble, disassemble, run, show the pipeline, and debug interactively. The terminal runs the same engine as the window, so results are identical. It is handy over SSH, for quick checks, and for scripts — a teacher's worksheet can be a list of debugger commands.

All commands start with python3 -m emips (run from the eMIPS folder, or anywhere once installed with pip). The transcripts below are real output — the test suite re-runs them.

4.1 Overview

Command Does
asm FILE assemble: print the listing, optionally write Intel HEX
dis FILE.hex disassemble the words of an Intel HEX file
run FILE run a program; then print the registers (and more)
pipe FILE run on the 5-stage pipeline: chart, CPI, stalls, events
debug [FILE] the interactive debugger
gui [FILE] open the window

python3 -m emips COMMAND --help lists every option of a command.

4.2 Options shared by several commands

Option Commands Meaning
--release R1|R2|R3|R5|R6 all the MIPS32 release (default R5)
--little all little-endian (default big)
--numeric asm, dis, debug registers as $8 instead of $t0
--strict asm, run, pipe, debug strict mode: no pseudo-instructions
--noreorder asm, run, pipe, debug start in .set noreorder (no automatic delay-slot nop)
--boot kernel|user|reset run, pipe, debug the start state (default kernel, like MARS); on the Malta reset runs the boot monitor from the reset vector first (unless the program has code at 0xbfc00000), and user needs --mmu tlb (Phase 5, The boot monitor)
--exceptions cp0|stop run, pipe, debug take exceptions like the hardware (default) or stop
--no-syscalls run, pipe, debug syscall raises the exception instead of the services
--keys TEXT run, pipe, debug type TEXT on the memory-mapped keyboard
--pipeline run, debug 5-stage pipeline: a step is a clock cycle
--no-forwarding run, pipe, debug the pipeline without forwarding paths
--caches run, pipe, debug the L1 caches of a MIPS 24K: 32 KB instruction and data cache, 4-way, 32-byte lines
--icache / --dcache SIZE[:WAYS[:LINE]] run, pipe, debug one cache of that shape (16K, 8K:2:32; none = off)
--cache-parity run, pipe, debug the caches have parity (ErrCtl.PE, the Cache Error exception)
--cache-init random|hardware run, pipe, debug cache contents after reset: random (default) or invalid
--l2 / --l3 SIZE[:WAYS[:LINE]] run, pipe, debug an L2 (256K: 8-way, 32-byte lines; 512K:4:64) and, below it, an L3 (2M)
--cache-ecc run, pipe, debug the L2 / L3 have ECC (ErrCtl.L2P, imprecise Cache Error)
--write-buffer run, pipe, debug the 24K write buffer: merges write-through stores, gathers uncached accelerated ones, sync empties it
--mem-timing KEY=N,... run, pipe, debug pipeline memory cycles: L2 (12), L3 (25), MEM (50), BEAT (1), BYPASS (4), WRITE (10) with caches; UTLB (3) a micro-TLB miss with the TLB; C2C (14) a miss served by another core's cache, UPG (8) an upgrade, INTV (4) until a waiting coherent store is visible, with --cores
--nonblocking run, pipe, debug pipeline: loads miss in the background (hit under miss)
--model 5-stage|24k run, pipe, debug the pipeline model: the textbook 5-stage pipeline (default) or the MIPS 24K's 8 stages with branch prediction (Phase 5)
--cores N run, pipe, debug a multi-core system of N cores (2–4): one memory, the Coherence Manager (coherent data caches, the shared L2), the Cluster Power Controller; the kernel / user boot starts every core at the entry, --boot reset core 0 only (Phase 5, 5.9); run prints the cores at the end, pipe (and run --pipeline) also every other core's cycles and CPI (the chart is core 0's); with --board malta a multi-core Malta (Phase 5, DMA)
--iocu run, pipe, debug with --board malta --cores N: an I/O Coherence Unit — the PCI DMA is coherent with the data caches (Phase 5, DMA)
--shadow-sets N run, pipe, debug GPR shadow sets, 1–16 (default 4, a 24K's most; Release 2+): what SRSCtl.HSS says, the sets an exception / vectored interrupt switches to (Phase 5, 5.10)
--no-header run, pipe, debug ignore the program's # eMIPS: line (without it, that line supplies the flags you do not give: What's in eMIPS); a combination of flags that does not go together is refused with the reason
--board SPEC asm, run, pipe, debug the board: flat (default: every physical address is RAM, the MARS layout) or malta[:RAM_MB[:SWITCHES[:MHZ]]] — the MIPS Malta (MHZ: the core's clock, default 10): the GT-64120's memory map, bus errors, the LEDs / display / switches, programs in kseg0 (Phase 5, A real board)
--disk [SLOT=]IMAGE run, pipe, debug an IDE disk on the Malta (with --board malta; repeatable): SLOT pri0 (the default, then pri1, sec0, sec1), IMAGE a file (its bytes are the sectors) or blank:SIZE (blank:8M); every run starts from the image (Phase 5, An IDE disk)
--mmu SPEC run, pipe, debug the MMU: fixed (default), bat, tlb[:N] (a 24K's TLB, N = 32), ftlb[:N[:SETSxWAYS]] (VTLB + FTLB, 64 + 128x4); a TLB takes +sc (segmentation control, EVA) and +pw (page table walker), e.g. ftlb+sc+pw (Phase 5)

They mean the same as the window's Settings (Phase 3, 3.11).

4.3 asm — assemble

$ python3 -m emips asm emips/gui/examples/sum_array.asm
00400000  3c081001  lui $t0, 0x1001                  # main:   la    $t0, nums
00400004  25080000  addiu $t0, $t0, 0                # main:   la    $t0, nums
00400008  24090004  addiu $t1, $zero, 4              # li    $t1, 4
0040000c  00005025  or $t2, $zero, $zero             # move  $t2, $zero
00400010  8d0b0000  lw $t3, 0($t0)                   # loop:   lw    $t3, 0($t0)
...

Each line: address, machine word, the instruction as the processor sees it, and the source line it came from — so you see what every pseudo-instruction became. An error stops with the line number: prog.asm: line 2: unknown instruction 'lii'.

--hex FILE.hex also writes the program as Intel HEX.

4.4 dis — disassemble Intel HEX

$ python3 -m emips asm emips/gui/examples/sum_array.asm --hex sum.hex
...
$ python3 -m emips dis sum.hex
00400000  3c081001  lui $t0, 0x1001
00400004  25080000  addiu $t0, $t0, 0
00400008  24090004  addiu $t1, $zero, 4
...

(asm --hex prints the listing too.) dis decodes every complete word in the file (data too — it cannot tell code from data). Use the same --release and --little the code was made for.

4.5 run — run a program

run runs until the program exits, runs past its last instruction, reaches a breakpoint, or --steps (default 100 000; on the Malta 1 000 000, its serial output is slow) are done. Its output appears as it is printed; when it reads input (read_int ...), type the input in the terminal (or pipe it in: echo 7 | python3 -m emips run prog.asm). Then the registers:

$ python3 -m emips run emips/gui/examples/sum_array.asm
sum = 18

--- 37 steps, pc = 0x0040004c, 37 cycles (exited)
$zero 0x00000000    $at 0x00000000    $v0 0x0000000a    $v1 0x00000000
  $a0 0x00000012    $a1 0x00000000    $a2 0x00000000    $a3 0x00000000
  $t0 0x10010010    $t1 0x00000000    $t2 0x00000012    $t3 0x00000006
...
   pc  0x0040004c    hi  0x00000000    lo  0x00000000
Option Meaning
--steps N stop after N steps
--break LOC stop before the instruction at LOC (repeatable)
--until LOC stop when LOC is the next instruction
--trace print what happens inside every instruction
--cp0 also print the CP0 registers
--fpu also print the FPU registers
--mem LOC[:WORDS] also print memory from LOC (repeatable)
--cache-stats also print the cache statistics: hits, misses, the 3 C's (Phase 5)
--tlb-stats also print the TLB statistics: lookups, hits, misses, exceptions, page walks (Phase 5)
--perf EVENT[,EVENT] set the performance counters to count these events (user and kernel mode) and print them at the end (Phase 5)
--pipeline run on the 5-stage pipeline and print the chart (as pipe)

A location (LOC) is an address (0x00400010), a source line number (12), a label (loop), or a register holding an address ($sp).

$ python3 -m emips run emips/gui/examples/factorial.asm --break fact --mem '$sp:4'
stopped at 0x00400020  addiu $sp, $sp, -8               line 13: fact:   addiu $sp, $sp, -8      # push $ra and $s0

--- 3 steps, pc = 0x00400020, 3 cycles
...
--- memory $sp
0x7fffeff0  00000000 00000000 00000000 00000000  ................

(The quotes around '$sp:4' stop the shell from replacing $sp.)

--trace prints, for every instruction, its fields, what the ALU did and where its operands came from, the memory access and the registers it changed:

$ python3 -m emips run emips/gui/examples/sum_array.asm --trace --steps 2

  decode: op[31:26]=001111 LUI | rs[25:21]=00000 $zero | rt[20:16]=01000 $t0 | immediate[15:0]=0001000000000001 4097
  ALU: b << 16; b = 0x00001001 from immediate 0x1001 (zero-extended) -> 0x10010000
  $t0: 0x00000000 -> 0x10010000
0x00400004: addiu $t0, $t0, 0   (I-format, 0x25080000)
  decode: op[31:26]=001001 ADDIU | rs[25:21]=01000 $t0 | rt[20:16]=01000 $t0 | immediate[15:0]=0000000000000000 0
  ALU: a + b; a = 0x10010000 from $t0 (register file); b = 0x00000000 from immediate 0x0000 (sign-extended) -> 0x10010000
...

The memory-mapped keyboard gets its keys from --keys (the newline is a key too):

$ python3 -m emips run emips/gui/examples/mmio_echo.asm --keys "ok\n"
...

(\n is typed literally here; in a shell, --keys $'ok\n' passes a real newline. Both work.)

4.6 pipe — the 5-stage pipeline

pipe runs the program on the 5-stage pipeline and prints the pipeline chart (one row per instruction, one column per cycle; -- is a stall in ID), the cycle count, the CPI and the stall cycles by cause. --events adds what happened each cycle:

$ python3 -m emips pipe emips/gui/examples/pipeline_hazards.asm --events --width 24
...
00400008   lw $t1, 0($t0)                     IF ID EX ME WB
0040000c   addu $t2, $t1, $t1                    IF -- ID EX ME WB
...
0040002c   mul $s0, $t7, $t7                                                   IF ID EX EX EX EX ME WB
00400030   addu $s1, $s0, $s0                                                     IF -- -- -- ID EX ME WB
...
24 cycles, 15 instructions retired, CPI 1.60
stall cycles: branch 1, ex-busy 3, load-use 1
    4  forward $t0: EX/MEM -> EX (lui $t0, 0x1001 -> addiu $t0, $t0, 0)
    5  load-use: $t1 from lw $t1, 0($t0)
...
   13  forward $t7: EX/MEM -> ID (or $t7, $t6, $t5 -> beq $t7, $zero, 0x00400034)
   13  beq $t7, $zero, 0x00400034: not taken
...
Option Meaning
--cycles N stop after N cycles (default 10 000)
--width N how many cycles the chart shows (default 40)
--events forwarding, stalls, branch decisions, flushes per cycle
--views the events plus the full view of the instructions in ID and EX
--cache-stats the cache statistics at the end (as run)
--tlb-stats the TLB statistics at the end (as run)
--perf EVENT[,EVENT] the performance counters (as run)
--no-forwarding without forwarding paths — compare the CPI 
$ python3 -m emips run emips/gui/examples/pipeline_hazards.asm --pipeline --no-forwarding
...
37 cycles, 15 instructions retired, CPI 2.47
stall cycles: ex-busy 3, no-forwarding 15

Rows marked (no code here) at the end are instructions the pipeline had already started fetching after the program's last instruction; they never execute.

4.7 debug — the interactive debugger

$ python3 -m emips debug emips/gui/examples/factorial.asm
eMIPS debugger — MIPS32 R5, big-endian, instruction mode. Type help.
=> 0x00400000  addiu $a0, $zero, 5              line 4: main:   li    $a0, 5
(emips) break fact
breakpoint at 0x00400020  addiu $sp, $sp, -8               line 13: fact:   addiu $sp, $sp, -8      # push $ra and $s0
(emips) continue
breakpoint
   0x00400008  nop
=> 0x00400020  addiu $sp, $sp, -8               line 13: fact:   addiu $sp, $sp, -8      # push $ra and $s0
(emips) continue
breakpoint
   0x00400044  nop
=> 0x00400020  addiu $sp, $sp, -8               line 13: fact:   addiu $sp, $sp, -8      # push $ra and $s0
(emips) regs $a0 $ra
   $a0 = 0x00000004  4
   $ra = 0x00400048  4194376
(emips) delete fact
(emips) finish
   0x0040005c  nop
=> 0x00400048  mul $v0, $v0, $s0                line 21: mul   $v0, $v0, $s0
(emips) regs $v0
   $v0 = 0x00000018  24
(emips) quit

How to read it:

  • => is the next instruction (not executed yet), with its source line. In pipeline mode it is the instruction about to enter EX.
  • The indented line before it is the instruction just executed and what it changed (; $t3 = 0x00000003, ; [0x7fffeff8] = 0x0040000c). Here it is the nop in a delay slot (the jump's, or the jal's).
  • The second continue stopped in the recursive call fact(4) ($a0 = 4); finish ran until that call returned to fact(5) — $v0 = fact(4) = 24.

Start it without a file and use load FILE at the prompt. Press Ctrl+C to stop a long run (the debugger stays), Ctrl+D or quit to leave. When the program reads input, the debugger asks for it (program input>) — or give it beforehand with input TEXT.

4.8 Debugger commands

help lists them; help COMMAND explains one. Short forms are in brackets.

Running

Command Does
step [N] (s) N instructions — or N clock cycles in pipeline mode
next [N] (n) like step, but a call (jal, jalr, bal, balc ...) runs to its return as one step
back [N] undo N steps
continue [N] (c, run, r) run until a breakpoint, the end, an error or an input request (at most N steps)
stepline [N] (sl) run to the next source line — a C line of a compiled program, a source line of an assembly one; into calls
nextline [N] (nl) like stepline, but a call runs as one step
until LOC (u) run until the instruction at LOC is next
finish run until the current function returns to its caller (by the call stack: a recursive call returning to the same address does not stop it)
reset restart the program (breakpoints and given input are kept)

Breakpoints: break LOC (b) sets one, break alone lists them, delete LOC (d) or delete all removes them. For a compiled program (an ELF with line information) LOC can be a C line — 17 (the current file; main's before the program gets there) or file.c:17 — or a function name; a line that starts in several places (a for with its condition and increment) gets a breakpoint on each.

Looking

Command Shows
regs all 32 registers, PC, HI, LO (* = changed by the last command)
regs $t0 $sp ... some registers, hex and decimal
cp0 PC, HI, LO, Status, Cause, EPC, BadVAddr, Count, Compare, IntCtl, SRSCtl, SRSMap (in Debug Mode Debug, DEPC, DESAVE), FCSR
srs / srs N the interrupt mode (compatibility / vectored), the next vector, the GPR shadow sets (current, previous, the exceptions' set, SRSMap) / set N's registers
ejtag / ejtag dint EJTAG: Debug Mode or not and what entered it, the Debug register (single step SSt, LSNM, CountDM, IEXI), DEPC, DESAVE, the DCR, the debug vector, the hardware breakpoints and watch registers / request a debug interrupt (the DINT input) (Phase 5)
probe / probe on [trap] [boot] / probe off / probe load FILE / probe break / probe fastdata W... / probe mem ADDR [WORDS] / probe profile [on|off] / probe rate N the TAP's state, the ECR and the probe's last processor accesses / connect an EJTAG probe (ProbEn; trap: the debug handler from its memory at 0xff200200; boot: EJTAGBOOT) / remove it / load a file's dmseg bytes into its memory / EjtagBrk / words for FASTDATA / its memory / collect PC samples, show where they fell / the sample rate (Phase 5)

fpu $f0–$f31 as single and double, FCSR
mem LOC [WORDS] (x) memory as words and text (default 16 words); mem -p ADDRESS dumps physical memory
translate LOC (t) the physical address the MMU makes of a virtual one, and how (Phase 5, 5.8)
cache every cache: its shape, valid lines, hit rate
cache stats [reset] hits and misses per kind of access, the 3 C's, evictions, the write buffer; reset starts them again
cache last the cache accesses of the last step (fetch and data; IF and MEM in pipeline mode)
cache I|D|L2|L3 the sets of that cache holding lines
cache D set N one set: each way's tag, age (LRU), dirty / locked, data
cache D LOC how LOC is cut into tag | index | offset, and its set
cache LOC where the line of LOC is, in every cache

tlb the TLB (--mmu): the entries in use, Wired, Random, the ASID; the six entries of a BAT

tlb set N the ways of FTLB set N (--mmu ftlb)

dis [LOC] [N] disassembly (default: around the current instruction)
list [LINE|LOC] (l) source lines (=> current, * breakpoint); a compiled program: its C file (list 17, list file.c:17, list main)
bt (backtrace) the call stack: the calls not returned yet, innermost first — function, address, source line

Tools

Command Does
decode WORD an instruction word: its fields and instruction
encode INSTRUCTION the machine word(s) of an instruction (pseudo: every word)
ref TEXT instructions matching TEXT (a pseudo-instruction is explained) 
$ python3 -m emips debug emips/gui/examples/sum_array.asm
(emips) decode 0x8fa80004
0x8fa80004  lw $t0, 4($sp)    (Load Word, I-format)
  op[31:26]=100011 (LW)  base[25:21]=11101 ($sp)  rt[20:16]=01000 ($t0)  offset[15:0]=0000000000000100 (4)
(emips) ref blt
blt is a pseudo-instruction; the assembler writes: slt $at, ... + bne $at, $zero, label
bltz rs, label                   Branch on Less Than Zero  [since R1, delay slot]
bltzal rs, label                 Branch on Less Than Zero and Link  [since R1, removed in R6, delay slot]
bltzall rs, label                Branch on Less Than Zero and Link Likely  [since R1, removed in R6, delay slot]
bltzl rs, label                  Branch on Less Than Zero Likely  [since R1, removed in R6, delay slot]
(emips) print 0.1
hex 0x3dcccccd   unsigned 1036831949   signed 1036831949   text '=...'
bin 0011 1101 1100 1100 1100 1100 1100 1101
single 0.10000000149011612   (normal: +1.fraction × 2^(123 − 127) = +1.fraction × 2^-4)
double 0.1   (normal: +1.fraction × 2^(1019 − 1023) = +1.fraction × 2^-4)
note: single precision cannot hold 0.1 exactly: stored 0.10000000149011612 (error +1.49e-09)

   0x00400048  syscall
   (ended)

Setup

Command Does
mode instruction|pipeline switch the mode (restarts the program)
set release R1..R6 the MIPS32 release
set endian big|little the byte order
set forwarding on|off the pipeline's forwarding paths
set model 5-stage|24k the pipeline model of mode pipeline
set cores 1..4 the number of cores
set iocu on|off the I/O Coherence Unit of a multi-core Malta (like --iocu)
set shadow-sets 1..16 GPR shadow sets (1 = the normal GPRs only)
set strict on|off strict mode (no pseudo-instructions)
set reorder on|off automatic delay-slot nops
set boot kernel|user|reset the start state
set exceptions cp0|stop take exceptions, or stop the simulation
set syscalls on|off the system-call services
set names abi|numeric $t0 or $8
set icache|dcache|l2|l3 SIZE[:WAYS[:LINE]] a cache of that shape (none = without)
set write-buffer on|off the write buffer
set mmu SPEC the MMU, as --mmu
set board flat|malta[:RAM_MB[:SWITCHES[:MHZ]]] the board (like --board); the program is assembled again
set disks [SLOT=]IMAGE[,...]|none the Malta's IDE disks (like --disk); the program restarts with them
load FILE load another program (.asm or .hex)
quit (q) leave

Changing an option re-assembles or restarts the program. If it no longer assembles, nothing runs until it does:

$ python3 -m emips debug emips/gui/examples/sum_array.asm
(emips) set strict on
error: line 6: la is a pseudo-instruction (strict mode); write: lui rt, %hi(label) + addiu rt, rt, %lo(label)  [main:   la    $t0, nums]
(emips) continue
error: no program loaded (load FILE)
(emips) set strict off
=> 0x00400000  lui $t0, 0x1001                  line 6: main:   la    $t0, nums

4.9 Scripts

Instead of typing at the prompt, give the commands with -c (separated by ;) or in a file with -x (one per line, # starts a comment). Each command is printed before its output, so the result reads like a session — useful for worksheets, for checking answers, and for comparing two versions of a program:

$ python3 -m emips debug emips/gui/examples/sum_array.asm -c 'break loop; continue; continue; regs $t2'
(emips) break loop
breakpoint at 0x00400010  lw $t3, 0($t0)                   line 9: loop:   lw    $t3, 0($t0)
(emips) continue
breakpoint
   0x0040000c  or $t2, $zero, $zero
=> 0x00400010  lw $t3, 0($t0)                   line 9: loop:   lw    $t3, 0($t0)
(emips) continue
breakpoint
   0x00400024  nop
=> 0x00400010  lw $t3, 0($t0)                   line 9: loop:   lw    $t3, 0($t0)
(emips) regs $t2
   $t2 = 0x00000003  3

A script file, lab1.cmd:

# Lab 1: watch the sum grow
break loop
continue
regs $t2
continue
regs $t2

python3 -m emips debug emips/gui/examples/sum_array.asm -x lab1.cmd

With a script, the program's input comes from the terminal (or a pipe): echo 7 | python3 -m emips debug prog.asm -c "continue".

Add --stop-at-end to stop when the program runs past its last instruction instead of reporting an error.

4.10 gui

python3 -m emips gui [FILE.asm | FILE.hex]

opens the window (Phase 3), optionally with a file. If neither PyQt6 nor PySide6 is installed it says so and how to install one.

4.11 cc — build a C program

python3 -m emips cc prog.c [more.c lib.S] [-o prog.elf] [--release R1|R2|R3|R5|R6]
                    [--little] [-O 0|1|2|3|s] [-v]

Builds an ELF executable for eMIPS with clang or a MIPS GCC (and GNU ld or ld.lld): crt0, libemips.c and the sources, linked for the eMIPS memory map (Phase 2, 2.18). -v prints the commands it ran. run, pipe and debug take a .c file too (built for the session's release and byte order) and every command takes the .elf: dis prog.elf prints its listing — the disassembly with each C line above its instructions.
