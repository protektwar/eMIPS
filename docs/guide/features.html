Settings that go together

eMIPS offers only combinations it models correctly. The release decides what the processor has (shadow register sets from Release 2, segmentation control from Release 3, the page table walker from Release 5, multi-core systems of Release 2+ cores; an IOCU only on a multi-core Malta); the Malta board runs programs in kernel mode, in user mode only with a TLB; C programs and ELF executables use the flat memory layout. Choosing a release or a board adjusts what depends on it and says so (Settings shows the reason as a note, the toolbar in the status bar); a value that does not fit is greyed out, its reason in its tooltip. On the command line a combination given on purpose that does not go together is refused with the reason.

A program's own settings: # eMIPS:

A program may say how it is meant to run, in a comment line anywhere in it, with the command line's flags:

# eMIPS: --board malta
# eMIPS: --cores 2 --caches --pipeline --model 24k
// eMIPS: --release R6          (in C; /* eMIPS: ... */ too)

Opening it (File → Open, Examples, Labs) sets the machine up so — the settings it names, the others of the machine at their defaults — and says which in the status bar. On the command line it supplies the flags you do not give; --no-header ignores it.
