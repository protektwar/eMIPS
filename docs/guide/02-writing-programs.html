Phase 2 — Writing programs

Guide contents · previous: Phase 1 — Getting started · next: Phase 3 — The GUI in depth

This phase is about the language: how a MIPS assembly program is written for eMIPS, what the assembler accepts, and how a program talks to the outside world — system calls, the memory-mapped console, exceptions, interrupts and the floating-point unit.

The syntax is the one of GNU as, which is also what MARS and SPIM use, so most course material works unchanged. Where eMIPS differs from MARS it is listed in 2.15.

2.1 The shape of a program

# output: Hello, MIPS!\n
        .data                           # data goes here
greeting: .asciiz "Hello, MIPS!\n"
        .text                           # instructions go here
main:   la    $a0, greeting             # $a0 = address of the text
        li    $v0, 4                    # service 4 = print_string
        syscall
        li    $v0, 10                   # service 10 = exit
        syscall
  • One statement per line: an instruction, a directive (a word starting with .) or nothing. A line may start with one or more labels (name:).
  • Comments start with # and run to the end of the line.
  • Labels name an address: letters, digits, _, . and $, not starting with a digit. Case matters (Loop ≠ loop).
  • Segments: .text for instructions, .data for data. You can switch back and forth as often as you like.
  • The program starts at the label main (or __start, or the beginning of .text).
  • A program ends with the exit system call (li $v0, 10 + syscall). Without it the processor runs past the last instruction and the simulation stops with a message saying so.
Segment Starts at For
.text 0x00400000 your instructions
.data 0x10010000 your data
.ktext 0x80000180 the exception handler (kernel code) — 2.11
.kdata 0x90000000 kernel data

Each can be given an address: .text 0x00400100, .data 0x10020000. The stack pointer $sp starts at 0x7fffeffc and the heap (sbrk) at 0x10040000.

2.2 Registers

MIPS has 32 general-purpose registers. Write them by name or number: $t0 and $8 are the same register.

Number Name Use
$0 $zero always 0 (writes are ignored)
$1 $at reserved for the assembler (pseudo-instructions)
$2–$3 $v0–$v1 function results; $v0 = syscall number
$4–$7 $a0–$a3 function arguments
$8–$15 $t0–$t7 temporaries (a call may change them)
$16–$23 $s0–$s7 saved (a function must preserve them)
$24–$25 $t8–$t9 temporaries
$26–$27 $k0–$k1 reserved for the exception handler
$28 $gp global pointer
$29 $sp stack pointer
$30 $fp ($s8) frame pointer
$31 $ra return address (written by jal)

Besides these: HI and LO (results of mult / div, read with mfhi / mflo), the PC, the floating-point registers $f0–$f31 (2.13) and the coprocessor-0 registers, accessed by number with mfc0 / mtc0 (2.11).

2.3 Instructions and operands

An instruction is a mnemonic followed by operands separated by commas. The order is the MIPS manual's: destination first.

        addu  $t2, $t0, $t1       # $t2 = $t0 + $t1          (three registers)
        addiu $t0, $t0, -4        # $t0 = $t0 - 4            (register + immediate)
        sll   $t1, $t1, 2         # $t1 = $t1 << 2           (shift amount 0..31)
        lw    $t3, 8($sp)         # $t3 = memory[$sp + 8]    (offset(base))
        sw    $t3, 0($t0)         # memory[$t0] = $t3
        beq   $t0, $t1, done      # branch to a label
        j     loop                # jump to a label
Operand Written Range
register $t0, $8
signed immediate (addi, addiu, slti ...) -5, 0x7fff −32768 … 32767
unsigned immediate (andi, ori, xori) 255, 0xffff 0 … 65535
upper immediate (lui) 0x1001 0 … 65535
memory offset(base), (base) offset −32768 … 32767
branch target a label (or an absolute address 0x00400010) ±128 KB around the branch
jump target (j, jal) a label the same 256 MB region

A value that does not fit is an error that names the range, e.g. andi: immediate -1 out of range 0..65535 — use li (below) to put a large constant in a register first.

Loads and stores move bytes (lb, lbu, sb), halfwords (lh, lhu, sh) or words (lw, sw). The address must be a multiple of the size (except in Release 6), or the processor raises an address error exception. lb / lh sign-extend, lbu / lhu zero-extend.

The complete list of instructions, with their syntax and encoding, is in the GUI under Tools → Instruction Reference (or ref TEXT in the terminal debugger).

2.4 Numbers, characters and expressions

Written Value
42, -7 decimal
0x2a, 0X2A hexadecimal
0b101010 binary
'A', '\n' the character's code (65, 10)

Wherever a number goes you can write an expression: + - * /, << >>, & |, unary - and ~, parentheses, labels and constants: buffer+4, (SIZE-1)*4, 'a'-'A'.

Named constants: .eqv NAME, value (also .equ, .set NAME, value):

# output: 40
        .eqv  COUNT, 10
        .text
main:   li    $a0, COUNT*4
        li    $v0, 1
        syscall
        li    $v0, 10
        syscall

%hi(label) and %lo(label) give the two halves of an address for lui + addiu / lw — exactly what la expands into.

2.5 Data

Directive Reserves
.word v, v, ... 32-bit words (aligned to 4)
.half v, ... 16-bit halfwords (aligned to 2)
.byte v, ... bytes
.float v, ... IEEE single-precision numbers (aligned to 4)
.double v, ... IEEE double-precision numbers (aligned to 8)
.ascii "text" the characters, no terminator
.asciiz "text" the characters and a 0 byte (a C string)
.space n n zero bytes
.align n skip to the next multiple of 2ⁿ

.word, .half, .float and .double align themselves, and a label right before them moves with the data. For example:

        .data
count:  .word   3               # 0x10010000
flags:  .byte   1, 2, 3         # 0x10010004 .. 0x10010006
total:  .word   0               # 0x10010008 (one padding byte before it)
name:   .asciiz "MIPS"          # 0x1001000c .. 0x10010010 (with the 0 byte)
pi:     .float  3.14159         # 0x10010014 (aligned to 4)
big:    .double 2.5             # 0x10010018 (aligned to 8)
buffer: .space  16              # 0x10010020: 16 zero bytes

Strings may contain \n, \t, \r, \0, \\, \" and \'.

Byte order. By default eMIPS is big-endian: the word 0x12345678 is stored as the bytes 12 34 56 78. Choose little-endian with Configure → Byte Order (GUI) or --little (terminal); the Memory pane shows the bytes as they are stored.

2.6 Pseudo-instructions

Pseudo-instructions are conveniences: the assembler turns each one into one or more real instructions, exactly as GNU as does. The Disassembly pane shows what each became.

You write The assembler writes
move $t0, $t1 or $t0, $t1, $zero
li $t0, 5 addiu $t0, $zero, 5
li $t0, 0xffff ori $t0, $zero, 0xffff
li $t0, 0x12345678 lui $t0, 0x1234 + ori $t0, $t0, 0x5678
la $t0, label lui $t0, %hi(label) + addiu $t0, $t0, %lo(label)
neg $t0, $t1 / negu sub / subu $t0, $zero, $t1
not $t0, $t1 nor $t0, $t1, $zero
beqz $t0, L / bnez beq / bne $t0, $zero, L
blt $t0, $t1, L slt $at, $t0, $t1 + bne $at, $zero, L
bge, bgt, ble (and ...u) slt / sltu $at, ... + beq / bne
lw $t0, label lui $t0, %hi(label) + lw $t0, %lo(label)($t0)
sw $t0, label lui $at, %hi(label) + sw $t0, %lo(label)($at)
lw $t0, 70000($t1) lui + addu + lw (offset too large)

nop (= sll $zero, $zero, 0), b (= beq $zero, $zero) and bal are real instructions, not pseudo-instructions.

Pseudo-instructions use $at as scratch — that is why your programs should not use $at themselves. .set noat forbids it, and then any pseudo-instruction that needs it is an error.

Strict mode (Configure → Settings → Assembler, or --strict) turns pseudo-instructions off, so you write every machine instruction yourself. Each pseudo-instruction then is an error that tells you what to write instead:

line 1: li is a pseudo-instruction (strict mode); write: addiu rt, $zero, imm / ori rt, $zero, imm / lui rt, hi + ori rt, rt, lo

2.7 Branch delay slots

On a MIPS processor (before Release 6) the instruction after a branch or jump always executes, whether the branch is taken or not. That instruction is the branch's delay slot. It is not a quirk of the simulator: it is how the 5-stage pipeline works (the branch is decided in ID, when the next instruction has already been fetched).

eMIPS has two ways to deal with it:

  • .set reorder (the default, as in GNU as): the assembler puts a nop into every delay slot. You write code as if branches took effect immediately; the Disassembly shows the added nops.
  • .set noreorder: you fill the delay slot yourself — the next instruction you write is the delay slot. This is what real MIPS assembly programmers do, to make the slot useful:
# output: 50
        .set  noreorder
        .text
main:   li    $t0, 0
        li    $t1, 5
loop:   addiu $t1, $t1, -1
        bnez  $t1, loop
        addiu $t0, $t0, 10      # the delay slot: runs on every round, 5 times
        move  $a0, $t0
        li    $v0, 1
        syscall
        li    $v0, 10
        syscall

The branch-likely instructions (beql, bnel, ... — removed in Release 6) execute their delay slot only when the branch is taken. jal and the other links store the address after the delay slot (the branch address + 8) in $ra.

You can switch between the two modes anywhere in a program, and choose the default in Configure → Settings → Assembler (or --noreorder). The example File → Examples → Branch delay slots shows both.

2.8 Functions and the stack

jal label jumps to a function and saves the return address in $ra; jr $ra returns. By convention arguments go in $a0–$a3 and the result in $v0:

# output: 7
        .text
main:   li    $a0, 3
        li    $a1, 4
        jal   add2              # $ra = the return address
        move  $a0, $v0          # the result
        li    $v0, 1
        syscall
        li    $v0, 10
        syscall

add2:   addu  $v0, $a0, $a1     # $v0 = $a0 + $a1
        jr    $ra               # back to the caller

A function that calls another function must save $ra (and every $s register it changes) on the stack first and restore them before returning. The stack grows down: reserve space by subtracting from $sp, release it by adding back. File → Examples → Function calls and the stack (a recursive factorial) shows the full pattern:

fact:   addiu $sp, $sp, -8      # make room for two words
        sw    $ra, 4($sp)       # save the return address
        sw    $s0, 0($sp)       # save $s0, which we are about to change
        ...                     # body (may call jal fact)
        lw    $s0, 0($sp)       # restore
        lw    $ra, 4($sp)
        addiu $sp, $sp, 8       # release the room
        jr    $ra

In the terminal debugger, next steps over a whole call and finish runs until the current function returns.

2.9 System calls

A program asks the "operating system" for a service with syscall: the service number goes in $v0, the arguments in $a0–$a3 (or $f12), and results come back in $v0 (or $f0). These are the services of MARS and SPIM:

$v0 Service Arguments → result
1 print_int $a0 = integer
2 print_float $f12 = float
3 print_double $f12 = double
4 print_string $a0 = address of a 0-terminated string
5 read_int → $v0
6 read_float → $f0
7 read_double → $f0
8 read_string $a0 = buffer, $a1 = its size
9 sbrk (allocate memory) $a0 = bytes → $v0 = address
10 exit
11 print_char $a0 = the character
12 read_char → $v0
17 exit2 (with a code) $a0 = exit code
34 print_hex $a0 = integer
35 print_binary $a0 = integer
36 print_unsigned $a0 = integer

Reading input: when the program executes a read_... service, the simulation waits: in the GUI the Console's input line lights up — type the value and press Enter; in the terminal, type it on the next line. read_string behaves like C's fgets: it stores at most $a1 − 1 characters, including the newline if it fits, then a 0 byte:

# input: Ada
# output: Your name? Hello, Ada\n
        .data
ask:    .asciiz "Your name? "
hello:  .asciiz "Hello, "
name:   .space  32
        .text
main:   la    $a0, ask
        li    $v0, 4
        syscall
        la    $a0, name         # read_string(name, 32)
        li    $a1, 32
        li    $v0, 8
        syscall
        la    $a0, hello
        li    $v0, 4
        syscall
        la    $a0, name         # "Ada\n" — the newline came with it
        li    $v0, 4
        syscall
        li    $v0, 10
        syscall

A number $v0 not in the table is not a service: the processor takes the real System Call exception (2.11). You can also switch all services off (Settings → Exceptions & I/O, or --no-syscalls) and handle syscall in your own handler.

2.10 The memory-mapped console

Besides system calls there is a simulated keyboard and display, as in MARS ("Keyboard and Display MMIO Simulator") and SPIM: four device registers at fixed memory addresses, read and written with ordinary lw / sw.

Address Register Meaning
0xffff0000 receiver control bit 0 Ready: a key is waiting; bit 1 Interrupt enable
0xffff0004 receiver data the key (reading it clears Ready)
0xffff0008 transmitter control bit 0 Ready: the display can take a character; bit 1 Interrupt enable
0xffff000c transmitter data write a character here to display it

The program must poll: wait until Ready is 1, then read or write the data register. The display stays busy for a few cycles after each character, and keys arrive one at a time:

# keys: hi\n
# output: hi\n
        .text
main:   lui   $s0, 0xffff       # $s0 = 0xffff0000, the device base
        li    $s1, 10           # '\n' ends the program
wait_rx: lw   $t0, 0($s0)       # receiver ready?
        andi  $t0, $t0, 1
        beqz  $t0, wait_rx
        lw    $t1, 4($s0)       # the key
wait_tx: lw   $t0, 8($s0)       # display ready?
        andi  $t0, $t0, 1
        beqz  $t0, wait_tx
        sw    $t1, 12($s0)      # show it
        bne   $t1, $s1, wait_rx
        li    $v0, 10
        syscall

Type the keys into the Console's MMIO keyboard field (GUI), with the keys TEXT debugger command, or with --keys TEXT on the command line. With the Interrupt enable bits set, the devices raise interrupts instead (receiver → hardware line 1 = Cause.IP3, transmitter → line 0 = Cause.IP2; see 2.12).

The device addresses are in kernel space: a program running in user mode cannot touch them (Settings → Memory & boot).

2.11 Exceptions and exception handlers

When an instruction cannot complete — an arithmetic overflow (add, addi, sub), a misaligned or forbidden address, an unknown instruction, a trap, a syscall / break — the processor raises an exception. Coprocessor 0 records what happened and the processor jumps to the exception handler at 0x80000180:

CP0 register Number After an exception it holds
Status $12 EXL = 1 (exception level: kernel mode, interrupts off)
Cause $13 ExcCode (bits 6–2): which exception; BD: it was in a delay slot
EPC $14 the address of the instruction that failed (its branch, if BD)
BadVAddr $8 the bad address (address errors)
ExcCode Name Raised by
0 Int an interrupt (2.12)
4 / 5 AdEL / AdES load or fetch / store at a bad address
8 Sys syscall (when no service handles it)
9 Bp break
10 RI reserved (unknown) instruction
11 CpU coprocessor unusable (e.g. FPU off, or mfc0 in user mode)
12 Ov integer overflow
13 Tr trap (teq, tge ...)
15 FPE floating-point exception

The handler is ordinary code in the .ktext segment. It reads Cause / EPC with mfc0, does its work using $k0 / $k1 (and saves any other register it touches), sets EPC to where the program should continue and returns with eret:

# output: overflow caught\n5
        .text
main:   li    $t0, 0x7fffffff   # the largest positive int
        li    $t1, 5
        addi  $t1, $t0, 1       # signed overflow: exception, $t1 is not changed
        move  $a0, $t1
        li    $v0, 1            # prints 5
        syscall
        li    $v0, 10
        syscall

        .kdata
saved:  .word 0, 0
kmsg:   .asciiz "overflow caught\n"

        .ktext 0x80000180       # the exception vector
handler: la   $k0, saved        # the handler uses $v0 and $a0: save them
        sw    $v0, 0($k0)
        sw    $a0, 4($k0)
        la    $a0, kmsg
        li    $v0, 4
        syscall
        la    $k0, saved        # restore them
        lw    $v0, 0($k0)
        lw    $a0, 4($k0)
        mfc0  $k0, $14          # EPC = the addi that failed
        addiu $k0, $k0, 4       # continue after it
        mtc0  $k0, $14
        ehb                     # let the EPC write finish before eret reads it
        eret

Notes:

  • ehb (execution hazard barrier, Release 2): a pipelined MIPS writes CP0 registers late, and an eret right after mtc0 $k0, $14 could still read the old EPC — and return to the failing instruction again. The instruction-level simulator does not need it; the MIPS 24K pipeline model does, as the chip does (Phase 5).

  • A real handler first checks which exception it got (mfc0 $k0, $13, then (Cause >> 2) & 31), because one handler serves all of them.

  • EPC + 4 skips the failing instruction — but if Cause.BD is set, EPC points at the branch before it; skipping is then more involved.
  • An exception with no handler at the vector stops the simulation with an explanation, e.g. "the CPU took exception AdEL (Cause.ExcCode 4, EPC 0x00400000) and jumped to the exception vector 0x80000180, but there is no handler there". For debugging you can make every exception stop the simulation instead: Settings → Exceptions & I/O → Stop the simulation, or --exceptions stop.
  • Programs normally start in kernel mode (like MARS). Settings → Memory & boot can start them in user mode — then mfc0, mtc0, eret and kernel addresses raise exceptions, the operating-system view — or in the hardware reset state (exceptions go to 0xbfc00380, FPU and interrupts off).

2.12 Interrupts and the timer

Interrupts are exceptions caused by something outside the instruction stream (ExcCode 0). An interrupt is taken when:

  • Status.IE (bit 0) is 1, Status.EXL and ERL are 0, and
  • its bit in Status.IM (bits 15–8) is 1, and its Cause.IP bit (bits 15–8) is set.
Line Cause / Status bit Source
IP0, IP1 8, 9 software (write Cause)
IP2 10 MMIO display (transmitter ready, if enabled)
IP3 11 MMIO keyboard (key ready, if enabled)
IP7 15 the timer

The timer: CP0 register Count ($9) counts up (by default every 2 cycles); when it becomes equal to Compare ($11) the timer interrupt is raised. Writing Compare clears it. The handler typically sets the next Compare and returns with eret — EPC is the interrupted instruction, which then runs normally.

File → Examples → Interrupts: CP0 timer and exception handler is a complete program: it enables the timer (Status = IM7 | IE), counts three ticks in its handler and prints timer interrupts: 3.

2.13 Floating point

The floating-point unit (coprocessor 1) has 32 registers $f0–$f31 and follows IEEE 754 exactly (rounding, infinities, NaNs, the five exception flags in FCSR).

  • A single (.s) uses one register. A double (.d) uses an even/odd pair before Release 6 — always name the even one ($f0, $f2 ...).
  • Load / store with lwc1 / swc1 (single) and ldc1 / sdc1 (double); move to / from integer registers with mtc1 / mfc1.
  • Arithmetic: add.s, sub.s, mul.s, div.s, sqrt.s, abs.s, neg.s, mov.s (and the .d versions).
  • Conversions: cvt.s.w (integer → single; the integer must be in an FP register — mtc1 it first), cvt.w.s (single → integer), cvt.d.s, cvt.s.d ...
  • Compare and branch: c.eq.s, c.lt.s, c.le.s set a condition flag; bc1t / bc1f branch on it.
  • System calls: print_float (2) / print_double (3) print $f12; read_float (6) / read_double (7) return in $f0.
# output: 2.5 is bigger\n
        .data
a:      .float 2.5
b:      .float 1.75
bigger: .asciiz " is bigger\n"
        .text
main:   la    $t0, a
        lwc1  $f0, 0($t0)       # $f0 = a
        lwc1  $f2, 4($t0)       # $f2 = b
        c.lt.s $f2, $f0         # condition = (b < a)
        bc1f  done              # false: nothing to say
        mov.s $f12, $f0
        li    $v0, 2            # print_float($f12)
        syscall
        la    $a0, bigger
        li    $v0, 4
        syscall
done:   li    $v0, 10
        syscall

The FPU is switched on when a program starts in kernel or user mode (as in MARS); in the hardware reset state it is off and any FPU instruction raises the CpU exception until the program sets Status.CU1.

2.14 MIPS32 releases (R1 to R6)

MIPS32 has evolved through several releases. eMIPS simulates each one; choose it in Configure → MIPS32 Release (GUI) or with --release (terminal). The default is R5, the complete pre-R6 instruction set.

Release What it adds (for a student)
R1 the original MIPS32
R2 ext / ins (bit fields), rotr, seb / seh, wsbh, 64-bit FPU registers, ehb
R3 EVA (kernel access to user memory) — microMIPS is not simulated
R5 everything above (default)
R6 a cleaned-up architecture: compact branches, new multiply / divide, IEEE 754-2008 FPU; removes branch-likely, the old mul encoding, HI/LO-based mult / div, ...

An instruction that does not exist in the chosen release is an assembly error: beql does not exist in MIPS32 R6. The instruction reference (Tools menu) lists, for each instruction, the release that introduced it and the one that removed it.

Release 6 compact branches (bc, balc, beqzc, bnezc, beqc, bltc ...) have no delay slot: the next instruction runs only if the branch is not taken. The instruction after a conditional compact branch is its forbidden slot — it may not be another branch or jump (under .set reorder the assembler inserts a nop when it would be). The ordinary branches (beq, bne, j, jal ...) still have a delay slot in R6.

# release: R6
# output: 250
        .text
main:   li    $t0, 0
        li    $t1, 5
loop:   addiu $t0, $t0, 10
        addiu $t1, $t1, -1
        bnezc $t1, loop         # compact: no delay slot
        lsa   $t2, $t0, $t0, 2  # R6: $t2 = ($t0 << 2) + $t0 = 5 * $t0
        move  $a0, $t2
        li    $v0, 1
        syscall
        li    $v0, 10
        syscall

Release 6 also changes floating point to the IEEE 754-2008 rules (for example how NaNs are encoded; the number converter in the Tools menu shows both).

2.15 Differences from MARS and SPIM

eMIPS behaves like a real MIPS processor and accepts GNU as syntax. Programs written for MARS usually run unchanged; these are the differences you may meet:

In MARS In eMIPS
no delay slots (by default) delay slots always exist; the assembler fills them with nop (.set reorder), so MARS programs still run
blt $t0, 5, L, mul $t0, $t1, 5 (immediate forms) not available — load the constant into a register first (li $t1, 5)
rem, seq, sge, sne ... not available — use div + mfhi, slt / xor
l.s, l.d, s.s, s.d, li.s use lwc1, ldc1, swc1, sdc1 (li.s: load from .float data)
.word 0:10 (repeat) .space 40 (zeroes) or list the values
div $t0, $t1, $t2 (three operands) div $t1, $t2 + mflo $t0 (div $zero, $t1, $t2 is the GNU form of the 2-operand instruction)
exceptions with no handler continue they jump to the vector like the hardware; without a handler the simulation stops and explains why

2.16 Intel HEX files

An Intel HEX file holds machine code and data as text records — what an assembler or compiler produces for loading into a real board. eMIPS both writes and reads it:

  • Write: File → Export → Intel HEX… (GUI) or python3 -m emips asm prog.asm --hex prog.hex.
  • Read: File → Open a .hex file, python3 -m emips gui prog.hex, python3 -m emips run prog.hex, or just look at it with python3 -m emips dis prog.hex.

A loaded HEX image is shown as a read-only disassembly (address, word, instruction; code and data separated). You can step, run and set breakpoints on its lines exactly as with source. Execution starts at the file's start-address record (type 05) if it has one, otherwise at its lowest address. The release and byte order you choose decide how the words are decoded.

2.17 Common assembly errors

Message What it means
unknown instruction 'lii' a typo, or an instruction eMIPS does not have (see 2.15)
xxx does not exist in MIPS32 R6 the instruction is not in the chosen release (2.14)
immediate 70000 out of range -32768..32767 the constant does not fit: use li into a register
GPR expected, got '5' a register was expected — load the value with li first
label 'loop' defined twice two labels with the same name
undefined symbol nowhere a label is used but never defined (check the spelling — case matters)
beq: branch target 0x00430d48 out of range the label is too far for a branch: branch over a j instead
instruction not word-aligned data (.byte, .ascii ...) in .text left the next instruction at an address that is not a multiple of 4: put .align 2 before it

2.18 Programs in C

eMIPS runs ELF executables — what a C compiler and linker produce — as well as assembly: run, pipe, debug, dis and the GUI open them, and python3 -m emips cc builds them. You need a C compiler for MIPS: clang (any clang can generate MIPS code) with ld.lld or a MIPS binutils (binutils-mips-linux-gnu), or a MIPS GCC (gcc-mips-linux-gnu, mips-mti-elf-gcc).

There is no C library: a program talks to eMIPS through the system calls of 2.9 and the console of 2.10, which emips.h wraps — print_int, print_string, print_char, print_hex, print_float, read_int, read_char, read_string, sbrk, exit, the MMIO registers (MMIO_RX_CONTROL ...) and MFC0 / MTC0 for kernel code. labs/c_primes.c counts the primes below 100:

#include "emips.h"

#define N 100

static char composite[N];

int main(void)
{
    int count = 0;
    for (int i = 2; i < N; i++) {
        if (composite[i])
            continue;
        count++;
        for (int j = i * i; j < N; j += i)
            composite[j] = 1;
    }
    print_string("primes below 100: ");
    print_int(count);
    print_char('\n');
    return 0;
}

Build it and run it (run also takes the .c itself and builds it first):

$ python3 -m emips cc docs/guide/labs/c_primes.c -O 0
wrote docs/guide/labs/c_primes.elf: run it with  python3 -m emips run docs/guide/labs/c_primes.elf

$ python3 -m emips run docs/guide/labs/c_primes.elf
primes below 100: 25
...

What cc puts around your code: crt0.S (sets $gp and $sp, clears .bss, calls main and ends the program with its return value, the exit2 service), libemips.c (memcpy, memset, memmove, memcmp, strlen — compilers call them by themselves) and the linker script emips.ld: code at 0x00400000, data at 0x10010000, the stack below 0x7FFFF000 — the memory map of assembly programs. The flags: -march from --release (R1 mips32, R2-R5 mips32r2, R6 mips32r6), o32, hard float, no position-independent code (-fno-pic -mno-abicalls), -G0, -g for the line table, -O1 (-O 0 keeps every statement, easier to follow).

eMIPS reads the ELF's release (EF_MIPS_ARCH: MIPS32 → R1, Release 2 → R5, Release 6 → R6) and byte order from its header, and the source line of every instruction from its DWARF line table: the debugger shows c_primes.c:14: if (composite[i]) beside the PC, break main stops at a function, and the GUI's listing has each C line above its instructions.

$ python3 -m emips debug docs/guide/labs/c_primes.elf -c "break main" -c c
(emips) break main
breakpoint at 0x00400400  addiu $sp, $sp, -40              c_primes.c:11: {
(emips) c
breakpoint
   0x00400038  nop
=> 0x00400400  addiu $sp, $sp, -40              c_primes.c:11: {

Debugging is at the level of C lines: stepline (sl) runs to the next C line — into a called function —, nextline (nl) over calls, finish back to the caller, bt lists the calls not returned yet, break file.c:LINE / break FUNCTION set breakpoints, list shows the C file. The call stack is kept by watching the program: every jal / jalr / bal that is taken pushes a frame, every jr $ra pops one — it works for assembly programs too. Not there: a C library (printf, malloc — use sbrk), the 64-bit division helpers (long long / and %), position-independent or dynamically linked programs, and microMIPS / MIPS16e code (refused when loading).
