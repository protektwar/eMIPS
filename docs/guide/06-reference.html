6.1 System calls

$v0 = service; arguments in $a0–$a3 / $f12; results in $v0 / $f0 (Phase 2, 2.9).

$v0 Service In Out
1 print_int $a0
2 print_float $f12
3 print_double $f12 ($f12/$f13)
4 print_string $a0 = address
5 read_int $v0
6 read_float $f0
7 read_double $f0
8 read_string $a0 = buffer, $a1 = size at most size − 1 characters, newline kept, 0 byte
9 sbrk $a0 = bytes $v0 = address (heap from 0x10040000)
10 exit
11 print_char $a0
12 read_char $v0
17 exit2 $a0 = exit code
34 print_hex $a0 e.g. 0x0000002a
35 print_binary $a0 32 digits
36 print_unsigned $a0

Any other number in $v0 takes the System Call exception.

6.3 CP0 registers and their bits

Read with mfc0 rt, $n, write with mtc0 rt, $n (kernel mode). The ones a student program uses:

0 Index (TLB) the entry tlbwi / tlbr use; tlbp puts the matching one here, bit 31 (P) = 1: no match
1 Random (TLB) the entry tlbwr writes: counts down every cycle from the last entry to Wired (a 10-bit LFSR skips a step now and then, against livelocks)

5, 2–4 SegCtl0–2 (segmentation control) two 16-bit segment configurations each: PA (15–9), AM (6–4: who may use it, mapped or not), EU (3), C (2–0)
5, 5–7; 6, 6 PWBase, PWField, PWSize, PWCtl (page table walker) the table's base, where each index lies in the address, how many bits it has, PWEn (31) on

6.4 The FPU control register (FCSR)

Read with cfc1 rt, $31, write with ctc1 rt, $31.

Bits Field Meaning
1–0 RM rounding: 0 nearest, 1 toward zero, 2 toward +∞, 3 toward −∞
6–2 Flags sticky IEEE flags since last cleared: V Z O U I (bit 6 … bit 2)
11–7 Enables trap (FPE exception) on V Z O U I
17–12 Cause the flags of the last operation (E, V, Z, O, U, I)
18 / 19 NAN2008 / ABS2008 2008 NaN and ABS/NEG rules (1 in Release 6, read-only)
23, 31–25 FCC0, FCC7–FCC1 condition codes of c.cond / bc1t (not in Release 6)
24 FS flush tiny results to zero

V = invalid operation, Z = divide by zero, O = overflow, U = underflow, I = inexact.

cache op, offset(base) (kernel mode, or CU0): op = operation × 4 + cache (0 instruction, 1 data, 3 L2, 2 L3); index operations name a line by way × way size + set × line size (an unmapped kseg0 address; the L2 / L3 use the physical address), hit operations by an address:

op Cache Operation
0x00 / 0x01 I / D Index Invalidate / Index Writeback Invalidate
0x04 / 0x05 I / D Index Load Tag (into TagLo, DataLo)
0x08 / 0x09 I / D Index Store Tag (from TagLo: how boot code initializes a cache)
0x10 / 0x11 I / D Hit Invalidate (dirty data is lost)
0x14 / 0x15 I / D Fill / Hit Writeback Invalidate
0x19 D Hit Writeback (memory updated, line stays)
0x1c / 0x1d I / D Fetch and Lock (the line is never replaced)
0x03 / 0x07 / 0x0b L2 Index Writeback Invalidate / Index Load Tag / Index Store Tag
0x0f L2 Index Store Data (from L23DataHi:L23DataLo)
0x13 / 0x17 / 0x1b / 0x1f L2 Hit Invalidate / Hit Writeback Invalidate / Hit Writeback / Fetch and Lock

The L3 operations are the L2 ones minus 1 (0x1a = Hit Writeback, L3).

synci offset(base) (any mode) writes the data-cache line back and invalidates the instruction-cache line; pref hint, offset(base) loads a line early (hints 0–7), writes one back and invalidates it (25) or allocates a zeroed line for a store (30); hint 25 also sends a gathered uncached accelerated block. sync empties the write buffer's waiting entries. Without caches all of them do nothing.

6.5 Exception codes

ExcCode Name Cause
0 Int interrupt
1 Mod TLB Modified: a store to a page with D = 0
2 TLBL TLB Refill (no entry) or Invalid (V = 0) on a load or a fetch; also RI / XI with PageGrain.IEC = 0
3 TLBS TLB Refill or Invalid on a store
4 AdEL address error on a load or an instruction fetch (misaligned, or kernel address in user mode)
5 AdES address error on a store
8 Sys syscall not handled by the services
9 Bp break
10 RI reserved instruction: unknown, not in this release, or not available in this model
11 CpU coprocessor unusable: FPU off, or CP0 instruction in user mode
12 Ov signed integer overflow (add, addi, sub)
13 Tr a trap instruction's condition was true
15 FPE floating-point exception (an enabled IEEE flag)
19 / 20 TLBRI / TLBXI a load from a read-inhibited / a fetch from an execute-inhibited page (PageGrain.IEC = 1)
23 WATCH a watch register matched a fetch, load or store (deferred in Cause.WP while EXL / ERL = 1)
24 MCheck Machine Check: a TLB write would make two valid entries match (Status.TS = 1)

Vectors: 0x80000180 (0x80000200 for interrupts with Cause.IV); with Status.BEV = 1, 0xbfc00380 (0xbfc00400). A TLB Refill taken with Status.EXL = 0 goes to 0x80000000 (0xbfc00200).

The debug exceptions (EJTAG) have no ExcCode either and change only Debug and DEPC: sdbbp (DBp), single step (DSS), a debug interrupt (DINT) jump to the debug vector 0xbfc00480 in Debug Mode; an exception in Debug Mode comes back there with its ExcCode in Debug.DExcCode (9 also for sdbbp, 30 for a cache error) (Debug Mode).

The Cache Error exception has no ExcCode and leaves Cause alone: a parity error found in a cache (Settings → Caches → parity, and ErrCtl.PE = 1) sets CacheErr, ErrorEPC and Status.ERL and jumps to 0xa0000100 — kseg1, so the handler does not use the broken cache — or 0xbfc00300 with Status.BEV = 1. An uncorrectable L2 / L3 ECC error is imprecise: the instruction that met it completes (a load gets the bad value) and the exception comes before the next one, with ErrorEPC pointing there; one met by an instruction fetch is taken at that fetch.

6.7 When the simulation stops

Besides normal ends (exit, a breakpoint, the cursor line, an input request, the step limit), the simulation stops with a message in the status bar and the Messages pane (GUI), or after stopped: (terminal). The assembler's messages are in Phase 2, 2.17.

Message (start) What happened What to do
... the program ran past its last instruction there is no exit at the end; the processor fetched beyond the code end the program with li $v0, 10 + syscall
... the CPU took exception XXX (Cause.ExcCode n, EPC 0x...) and jumped to the exception vector 0x..., but there is no handler there an exception happened (see 6.5) and there is no handler at the vector fix the instruction at EPC — or write a handler at that address, or stop on exceptions (Settings → Exceptions, --exceptions stop)
MipsException: AdEL exception in LW at 0x... Exceptions: stop is on and an exception happened as above; the registers show the state before the instruction
... the program is loaded at this address, but with the fixed mapping MMU kuseg is at PA = VA + 0x40000000 while Status.ERL = 0 ... Status.ERL changed after the program was loaded (in the reset state), so kuseg now maps somewhere else keep code that leaves the reset state in kseg0 / kseg1 (.ktext), or start with the default boot (6.9)
... the CPU took a debug exception (DBp, DEPC 0x...) and jumped to the debug vector 0xbfc00480, but there is no debug handler there an sdbbp, a single step or a debug interrupt entered EJTAG Debug Mode and nothing is at the debug vector write a debug handler (.ktext 0xbfc00480, ending with deret) — Debug Mode
ProbeWaitError: load from dmseg 0x... with ECR.ProbEn = 0 / ... the probe did not finish the processor access Debug Mode software used dmseg (0xff200000–0xff2fffff), which only a probe serves; there is none (or, in the FASTDATA area, it had no word to give): the core would wait forever connect one (probe on, the Debug tab), queue FASTDATA words (probe fastdata) — or keep the debug handler and its data in ordinary memory
Reserved Instruction on tlbwr, tlbp ... the TLB instructions with the fixed mapping MMU (which has no TLB) pick a TLB: --mmu tlb, Settings → Processor → MMU
UnmappedAddress: no TLB entry maps 0x... now a syscall service (print_string ...) or a view read an address that no TLB entry maps — possible when the program has its own refill handler touch the data with a load first, or let the boot firmware's handler map it
CP0RegisterError: CP0 register not modeled: MFC0 reg=20 sel=0 a CP0 register eMIPS does not have use the registers of 6.3
Intel HEX: line n: checksum mismatch / malformed record / unknown record type the HEX file is damaged or not Intel HEX regenerate it
the program waits for input a read_... service and no input given type it (Console / terminal), or input TEXT
step limit reached Run's step limit (Settings → Run) Run again to continue — or look for an endless loop

A program that never ends and never reads input — an endless loop — simply keeps running: press Pause (F6) or Ctrl+C in the terminal.

6.8 What is not simulated

eMIPS models a MIPS32 core with its CP0, FPU and the classic pipeline. Not included:

  • a TLB by default — addresses are translated by the Fixed Mapping MMU (Phase 5, 5.8), where the TLB instructions are reserved instructions and there is no supervisor mode; --mmu selects the others: tlb (a 24K's TLB, The TLB), bat, ftlb (VTLB + FTLB), with +sc (segmentation control, EVA) and +pw (the page table walker) — The other MMUs; XPA (more than 32 physical address bits) is not modelled;
  • bus errors — every physical address is RAM (never-written bytes read 0);
  • memory wait states without caches — then every access takes one cycle. The caches (L1, L2, L3) and the write buffer are simulated when turned on (Settings → Caches, --caches, --l2, --write-buffer): they hold the data, so stale copies, self-modifying code, merged and gathered stores behave as on a 24K, and in the pipeline mode misses, writes and sync cost cycles (Settings → Memory timing);
  • off-chip trace (the TCB's probe interface, PIB / TR_DATA) — MIPS Trace itself (PDtrace and the TCB's on-chip trace memory) is simulated, like EJTAG Debug Mode, the hardware breakpoints, the watch registers, the TAP with a probe and PC sampling; microMIPS / MIPS16e (jalx is a reserved instruction);
  • ASEs: MSA (SIMD), DSP, MT, MIPS-3D, paired-single floating point, COP2 (Coprocessor Unusable), the optional Release 6 modules;
  • an external interrupt controller on one core — EIC mode needs the GIC: a multi-core system (--cores 2), The GIC as an External Interrupt Controller;
  • CP0 hazards in the 5-stage model (ehb is a no-op there; the 24K model has them, Phase 5) and some CP0 registers;
  • with more than one core (Phase 5, 5.9): the CPC carries a command out at once (no power-up delays); the instruction mode and blocking caches are sequentially consistent, the weak ordering of the hardware shows with the 24K model / non-blocking caches (Memory ordering).

Pipeline model choices (documented in Phase 5, 5.3–5.4): store data is needed in EX (load → store stalls one cycle); the FPU blocks EX for its latency.

Where the MIPS32 manual leaves a result UNPREDICTABLE, eMIPS picks one and documents it — for example, division by zero gives HI = LO = 0xffffffff (pre-R6) or 0 (R6), and a branch in a delay slot takes the inner branch's target. The full list is emips.sim.DEVIATIONS:

python3 -c "from emips.sim import DEVIATIONS; print(*DEVIATIONS.items(), sep='\n')"

6.9 Frequently asked questions

My program works in MARS but not in eMIPS. See Phase 2, 2.15: most often an immediate operand where eMIPS (like the real assembler) wants a register (blt $t0, 5, L), a MARS-only pseudo-instruction (rem, l.s), or code that relies on exceptions being ignored.

Why is there a nop after every branch in the Disassembly? The branch delay slot: the instruction after a branch always executes on MIPS; the assembler puts a nop there for you (.set reorder). Write .set noreorder to fill it yourself.

Why does li $t0, 0x12345678 take two steps? It is two instructions (lui + ori); 32-bit constants do not fit in one.

Why does $t0 hold 0x10010000 after la $t0, nums? That is the address of nums — .data starts at 0x10010000. lw $t0, nums loads the value stored there.

The register I changed in the Registers pane... The views are read only — change values with instructions.

Step Back is slow. It replays the program from the start; in long programs set a breakpoint and run instead.

The CPI of my program is above 2 although there are few stalls. Short programs are dominated by filling and draining the pipeline (Phase 5, 5.6).

My handler at 0xbfc00380 (reset state) returns to address 0. While Status.ERL = 1 (after reset), eret returns to ErrorEPC, not EPC, and clears ERL. Boot code clears ERL first (mfc0, clear bit 2, mtc0) — and, like real boot code, runs from kseg0 / kseg1: clearing ERL moves kuseg up by 1 GB (the fixed mapping), so a program loaded in kuseg while ERL = 1 is no longer at its addresses afterwards.

With caches on, kseg1 shows an old value. The store went through kseg0 into the data cache (write-back); memory is updated when the line is written back (cache 0x19, or when it is replaced). This is what a real MIPS does — devices and boot code read memory, not the cache.

syscall prints nothing. Check $v0 (the service number) and the argument register; with System call services off, syscall takes an exception instead.

Can I use eMIPS for MIPS64? No — MIPS32 only (R1–R6). The assembler does not know MIPS64 instructions such as daddu, and as machine code they are reserved instructions.

Where are my settings stored? ~/.config/eMIPS/eMIPS.ini (Linux; the equivalent per-user folder elsewhere). Delete it to start fresh.

6.10 For teachers

Worksheets as debugger scripts. A file of debugger commands (-x) reproduces a session exactly — breakpoints, register values, pipeline charts — so a worksheet can be checked, or handed out with its expected output (Phase 4, 4.9):

python3 -m emips debug lab.asm -x worksheet.cmd > expected.txt

Checking students' programs. run prints the program's output first, then the registers; feed the input from a file and compare:

python3 -m emips run student.asm --steps 1000000 < input.txt > result.txt

Options worth fixing for an exercise: --strict (no pseudo-instructions), --noreorder (they must fill delay slots), --release R6, --boot user (operating-system exercises), --exceptions stop, --no-syscalls (write the handler yourself).

In the classroom. Pipeline mode with the speed slider at its slowest, the Datapath and the Pipeline chart side by side (drag the Pipeline tab next to the Datapath), and the forwarding box toggled live show hazards better than any slide. The dark or light theme (Configure → Theme) suits the projector; zoom the editor with Ctrl++.

Adding examples. Put an .asm file in emips/gui/examples/ and add it to EXAMPLES in emips/gui/examples/__init__.py with its expected output: it appears in File → Examples.

Translating the interface. python3 tools/extract_gui_strings.py ro creates emips/gui/translations/emips_ro.ts; fill it with Qt Linguist (or any text editor) — Configure → Language then offers it.

6.11 Glossary

Term Meaning
ALU arithmetic-logic unit: adds, compares, shifts ...
big- / little-endian the most / least significant byte of a word at the lowest address
bubble an empty slot in the pipeline, inserted by a stall
compulsory / capacity / conflict miss the 3 C's: the first access to a line / the program needs more lines than the cache holds / too many lines want one set (Phase 5)
index / offset / tag the address fields a cache uses: the set, the byte in the line, the rest of the physical address stored with the line
cache a small fast memory holding copies of memory lines; set, way, tag, line: Phase 5, 5.8
dirty line a cached line changed by stores and not yet written back to memory
CP0 coprocessor 0: the system control registers (Status, Cause, EPC ...)
CP1 coprocessor 1: the floating-point unit
CPI cycles per instruction
performance counter a CP0 register that counts events (cycles, instructions, cache misses, stall cycles ...) in the modes its control register selects
delay slot the instruction after a branch / jump, always executed (pre-R6)
EPC exception program counter: where eret returns
exception a forced jump to the handler when an instruction cannot complete
forwarding (bypassing) feeding a result to a later instruction before it is written back
hazard a reason an instruction cannot proceed normally in the pipeline
immediate a constant inside the instruction word
kernel / user mode privileged / restricted execution
MMIO memory-mapped I/O: devices read and written like memory
MMU memory management unit: translates virtual addresses to physical ones (the fixed mapping MMU, or a TLB)
TLB translation lookaside buffer: the table of page mappings a TLB-based MMU uses; refill, invalid, modified: its exceptions (Phase 5)
page / frame a block of virtual / physical memory (4 KB by default) that the TLB maps as a whole
ASID address space identifier: which process a TLB entry belongs to (unless it is global)
micro-TLB a tiny copy of recent translations next to the fetch unit (ITLB) or the load/store unit (DTLB); the main TLB behind them is the JTLB
VPN2 / PFN virtual page number of a page pair (VA bits 31..13 for 4 KB pages), matched in the TLB / physical frame number in an EntryLo: the frame's address ÷ 4 KB
refill handler the code at the TLB Refill vector (0x80000000) that loads the missing entry, usually from the page table (Phase 5)
page table the operating system's table of every page's EntryLo; Context points into it after a TLB miss
copy-on-write pages shared read-only until the first store, whose TLB Modified exception copies the frame (example copy_on_write.asm)
BAT block address translation: base-and-bounds relocation of whole segments instead of pages
FTLB / VTLB a set-associative TLB of one page size / the fully associative TLB beside it for any page size
EVA enhanced virtual addressing: segmentation control plus kernel loads and stores with user rights
page table walker hardware that refills the TLB from the page table in memory, without an exception
physical / virtual address where a byte is in the RAM / the address a program uses
pipeline register the latch between two stages (IF/ID, ID/EX, EX/MEM, MEM/WB)
pseudo-instruction assembler shorthand expanded into real instructions
release a version of the MIPS32 architecture (R1–R6)
sign- / zero-extension widening a value by copying its sign bit / adding zeros
